# 独立仓库课程路线

每章是完整、独立可运行的代码快照。Git 历史用于维护各章，读者通过章节 README 学习。

下面是计划中的仓库命名；除当前第 00 章外，其余尚未创建，不把规划中的仓库写成可点击的已发布链接。

| 章 | 仓库名 | 本章问题 | 主要可观察结果 |
| --- | --- | --- | --- |
| 00 | `godot-netcode-00-baseline` | 如何让双端共享物理世界与规则 | 本地角色撞墙，双端录制输入得到相符检查点 |
| 01 | `godot-netcode-01-tcp` | 两个进程如何建立连接并交换消息 | 连接、断开、长度前缀、拆包与多消息解析 |
| 02 | `godot-netcode-02-authority` | 谁决定玩家的实际位置 | 客户端上传输入，服务端计算并广播多玩家状态 |
| 03 | `godot-netcode-03-network-lab` | 延迟和抖动如何影响体验 | 可调延迟、抖动、队列与观测面板 |
| 04 | `godot-netcode-04-prediction` | 为什么本地预测能改善操作响应 | 自己立即移动，同时看见预测分歧 |
| 05 | `godot-netcode-05-reconciliation` | 如何修正错误而保留未确认输入 | 输入确认、历史状态、纠正与重演 |
| 06 | `godot-netcode-06-interpolation` | 正确状态如何显示得连续 | 远端插值和本地纠正平滑 |
| 07 | `godot-netcode-07-udp` | 消息不保证送达时怎么办 | 丢包、乱序、重复包、消息时效性 |
| 08 | `godot-netcode-08-kcp` | 可靠传输的收益和代价是什么 | 相同条件下对比 TCP、UDP 策略与 KCP |
| 09 | `godot-netcode-09-protobuf` | 如何管理消息结构和协议演进 | Protobuf 编码、兼容性与大小对照 |

Socket 是接口，TCP/UDP 是传输协议，KCP 提供可靠传输机制，Protobuf 处理序列化。它们承担不同职责，不视为同一维度的升级替换。

TCP 阶段的延迟/抖动实验主要模拟应用层消息延后，不把它宣称为 TCP 底层丢包和拥塞仿真。UDP 章再直接实验数据报丢失、乱序和重复；需要比较实际 TCP/KCP 丢包行为时，再引入合适的链路仿真手段。

## 每章交付约定

1. 独立仓库、公开托管、完整代码与资源，不依赖邻章运行。
2. README 说明本章问题、前置知识、版本、启动命令、实验步骤与结果。
3. 列出相较前章的关键变化和关键文件，不要求读者自行浏览提交历史。
4. 提供与本章行为相关的验证方法，并说明验证边界。
5. 后续章节完成后，更新前后章导航；未完成章节明确标记为规划中。

预计后续增加更复杂地图、移动平台和动态物理交互，但这些不会提前塞进基础网络章节。
